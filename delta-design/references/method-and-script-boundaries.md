# 构型方法与脚本边界

## 稳定的方法链

| 层级 | 确定性验收 | 必须人工判断 |
|---|---|---|
| 冻结输入 | 文件存在、哈希、原子/位点映射、索引约定 | 父结构与自由度是否代表目标科学问题 |
| 枚举 | 理论计数、唯一性、组成、组合恒等式、重建抽检 | 约束是否遗漏真实自由度 |
| 对称去重 | 操作双射、群性质、容差平台、独立计数、类覆盖 | 占位母晶格与等价定义是否物理合理 |
| 描述符 | 对称不变、rank、duplicate、collision、复现 | 特征块是否可解释、是否值得增加复杂度 |
| 选样 | 覆盖、diversity、matched pair、近重复拒绝、快照哈希 | 样本预算、角色比例、最终候选批准 |
| 反馈选样 | prospective/retrospective 分离、group-aware 验证、候选池完整 | 模型风险是否允许进入下一轮 |

## 权威文档路由

- 目录和批次边界：`docs/规范/计算目录与批次命名规范.md`
- 脚本 I/O 和幂等：`docs/规范/脚本开发与产物规范.md`
- 当前稳定脚本接口：`docs/规范/脚本接口清单.md`
- 体系当前方法入口：`<体系>/04_docs/文档索引.md`、`技术路线/`、`科学决策/`
- 具体阶段事实：批次 `manifest.yaml`、`说明.md`、`01_source/`、`03_analysis/` 和 `04_docs/` 正式报告

先从文档索引定位现行版本。带日期的旧路线和批次脚本只作为历史证据，除非当前正式文档明确继承。

## 脚本职责

- 使用 `.delta/scripts/create_run.py` 注册新批次，使用 `update_indexes.py --check` 核验元数据。
- 只有 `docs/规范/脚本接口清单.md` 登记的 `.delta/systems/<体系>/scripts/` 才可视为现役体系入口；先用其 `--check-only`/`--dry-run`。
- 批次 `03_analysis/scripts/` 和 `01_source/inherited_*` 中的程序是该批次冻结方法与复现证据，不是跨阶段通用 CLI。复现原批次时从冻结输入执行；新科学问题应在新批次内建立新的确定性分析程序和输入哈希，而不是原地改旧脚本。
- 若确定性方法频繁跨体系复用，再评估提炼到 `.delta`；在此之前不要放入 Skill 的 `scripts/`。
- 所有生成器必须拒绝不同内容覆盖，提供只读模式，固定随机种子/tie-break，并将机器数据与中文报告分层输出。

## 面向未来阶段

Lu/Tm 掺杂、缺陷、声子超胞或其他离散自由度可复用“冻结—枚举—等价—表示—选样”链，但不得继承当前体系的位点数、元素、U 编号、母结构、构型数或描述符阈值。声子、CTE 和热导率若不包含离散构型选择，不应触发本 Skill；其 VASP 操作和结果审阅分别交给对应 Skill。
