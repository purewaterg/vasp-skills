# DELTA 经验沉淀

建立“实际工作 → 问题/纠正 → 经验候选 → 后续验证 → 成熟晋升或废止”闭环。保存可核查的外部工作记录，不保存 Agent 的完整思考过程。

## 输入与权威边界

要求提供已结束或已到明确检查点的任务范围、过程留痕、现象、尝试、纠正、证据和适用边界。先读
`docs/经验记录/README.md`；状态、收录门槛、案例格式和晋升路由均以该 README 为唯一来源，本 Skill 不复制。

正式科学决策、现行规范/工作流、权威脚本和冻结批次证据始终高于经验记录。经验只提供诊断线索；引用前必须核对状态、适用范围、验证日期和当前正式入口。

## 操作顺序

1. 只加载根 `AGENTS.md`、`docs/文档索引.md` 和经验 README；本任务只加载本 Skill，不预读其他 Skill，不递归展开案例或历史。
2. 从当前项目/体系入口确认现行规则，再按关键词检索相关案例；现行规范已完整覆盖的问题不重复记录。
3. 仅对真实任务的非平凡问题/纠正提出候选；普通日志、动态科研状态、一次成功或未验证猜测不进入经验层。
4. 优先更新同主题案例；确需新增或改动时，按 README 的路径、格式和索引同步要求执行，用短证据链接替代大日志。
5. 独立复现、负例或跨任务证据只能在单独验证/晋升任务中改变案例状态；生产型 Skill 只能提交候选，不能自行晋升。
6. 发现反证、环境淘汰或正式路线冲突时按 README 标记废止并保留替代入口，不删除原记录。
7. 输出本次检索、记录/不记录理由、证据充分性、未决验证和去向，并运行 Markdown 链接检查。

## 禁止事项

- 不启动或操作 VASP/MPI/生产队列，不改科研输入、结果、状态或阶段结论。
- 不把当前候选、U 编号、最低能结构、批次完成数、实时资源状态或科学参数写成经验。
- 不把单次成功、相关性、个人偏好或未复现猜测升级为规则。
- 不复制正式规范、完整审计报告、大型输出或已有脚本；案例应链接来源并提炼诊断价值。
- 不仅靠自然语言经验反复修补可确定执行的问题；达到成熟门槛后优先落实到脚本和测试。
- 不静默改写历史案例状态、证据或结论。

## 验收与输出

每个案例必须可回答：为何值得记录、证据在哪里、什么已失败、什么有效、验证到什么程度、何时不适用、当前状态、下一验证或晋升去向。索引与案例一致、所有链接有效，且没有复制动态科研事实或扩大科学结论。
