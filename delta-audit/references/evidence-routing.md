# DELTA 证据路由与判定边界

## 权威来源顺序

| 问题 | 首选来源 | 补充来源 | 不可单独作为结论 |
|---|---|---|---|
| 长期目录/状态/安全规则 | `docs/规范/计算目录与批次命名规范.md`、`docs/规范/脚本开发与产物规范.md` | 当前工作流、脚本接口、现役代码和测试 | 历史交接、历史备份中的 AGENTS 或规范 |
| 当前体系/批次状态 | `项目总目录.md`、体系 `目录.md`、批次 `manifest.yaml` + `说明.md` | `进度.md`、campaign、队列状态 | slug、mtime、报告标题 |
| 批次执行事实 | campaign、`.delta/runtime/` 状态、队列记录、公共验收产物 | 尾读运行日志 | PID、退出码、`OUTCAR` 或 `CONTCAR` 单项 |
| 冻结科学输入 | 批次 `01_source/` 清单、哈希、manifest、正式方法报告 | 上游批次机器产物 | 路径相似或当前文件内容 |
| 科学结论/路线 | 体系 `04_docs/科学决策/`、`技术路线/` 的现行日期版本，批次正式报告 | `03_summary/` 跨批次汇总 | 自动报告、旧讨论稿、机器验收 |
| 历史整改事实 | `docs/审计记录/` 对应日期报告 | 迁移备份 | 作为当前活动入口 |

发生冲突时不要机械规定“永远以某一文件为准”。先区分机器字段与人类表达的职责，再核对原始证据；无法确定就停止发布并列入人工复核。

## 四层状态

1. **登记/执行状态**：批次是否 planned/prepared/running/completed/stopped/failed/archived，任务是否真正启动或结束。
2. **技术验收**：输入、进程身份、退出码、输出完整性、电子/离子收敛是否满足对应阶段判据。
3. **科学有效性**：协议是否可比，结构/组成/赝势/标签/单位是否正确，失败或诊断结果能否进入目标分析。
4. **阶段决策**：证据是否足以回答科学问题并进入下一阶段。此层由正式科学审阅和人工确认承担。

禁止用低层状态自动推出高层结论。

## 当前与历史

- 先读根和体系文档索引，定位当前版本；日期较新的正式决策可修订旧路线，但必须保留旧文档的历史事实。
- 旧批次内脚本是该批次的可复现证据，不自动成为新阶段的通用入口。
- 若正式报告记录选择器 bug、协议修订、结构表示切换或路线废止，后续只能使用修订后的冻结版本；旧版本仅用于差异审计。
- 动态数字、候选编号、最低能结构、U 编号和批次状态永远从当前正式文档读取，不写入 Skill 规则。

## 只读范围

优先读 manifest、说明、索引、小型 JSON/CSV、哈希清单、正式 Markdown 和脚本 `--help`。诊断 VASP 时只尾读有限日志和 `OSZICAR`/`OUTCAR`，不完整扫描大型输出，不读 `WAVECAR`/`CHGCAR`。
